# RBT-113 runner brief: one wave, four sessions (Sa–Sd), two arms each

The coordinator (`session_01WKXr6PgNkscGhVc7Bzth9k`) launches these sessions after merging the RBT-113 design PR
and ruling on its design adversary.
- **The design** is pre-registered in `runs/RBT-113/PREREGISTRATION.md` (its latest amendment governs).
- **Your job is to run it exactly, not to improve it.** Change no script.

Your prompt names your session (Sa–Sd):

| session | arm A (default operator) | arm B (`--global-bias-sigma 0`, holistic salt 1) | seeds |
|---|---|---|---|
| Sa | O1 | Z1 | 1 2 3 |
| Sb | O2 | Z2 | 4 5 6 |
| Sc | O3 | Z3 | 7 8 9 |
| Sd | O4 | Z4 | 10 11 12 |

For each arm `ARM`:
- the arm directory is `runs/RBT-113/ARM`, holding one seed directory per seed (`1`, `2`, `3` for O1; `Z1`, `Z2`, `Z3`
  for Z1), each holding the three line runs `U/`, `D/`, `C/`;
- the durable label is `rbt-113-ARM` (checkpoint branch `ckpt/rbt-113-ARM`);
- the results branch is `results/RBT-113-ARM`, with **one PR per arm**.

An arm is nine `evolve` runs in sequence (3 seeds x U, D, C), each 24 generations of 40 + 40 solo-scored
individuals on 2 draws. Measured on this image: about 12.6 s per generation with 4 workers alone, so about 25 s per
generation per arm with two arms side by side at WORKERS=2: **about 1.5 h per arm, budget 2.25 h**.

## 0. Rules (binding)

- **Read first:** `runs/README.md` ("A run must outlive its container", rules 1–6), and the header of
  `runs/RBT-113/run_arm.sh`.
- **Read no result. No peeking at the tables.**
  - Follow progress **only** through `runs/RBT-113/ARM/state.json` (its `generation`, the arm's completed
    generations out of 216) and `scripts/durable.sh status`.
  - Do not open, `cat`, `tail`, `grep` or summarise any `run.log`, `lineage.jsonl`, `history.json`, any line run's
    `state.json`, or any genome. `run.log` prints fitness every generation.
  - If a step fails, read its traceback on stderr (or the last lines of the failing run's `run.log` **only after the
    python process has died**, and only the traceback) and nothing else.
  - If you see a result by accident, say so on the ticket, and use and post none of it.
- **Scope:** touch only your two arms' directories and branches. Change no shared file.
- **Ticket comments** (RBT-113) are operational only: launch, PRs, anything that went wrong. End each with the
  footer `_Generated by [Claude Code](https://claude.ai/code)_`.

## 1. Set up (once per session)

1. **Clone** the integration branch `claude/new-session-4cao7d` at (or after) the merged design commit, and work in
   that checkout. Do not switch its branch while an arm runs (§4 commits without switching).
2. **Venv:** `python -m venv ~/venv && ~/venv/bin/pip install -e '.[dev]'`, with no scipy (`python -c "import scipy"`
   must fail). Then `export PATH=~/venv/bin:$PATH` in every shell that launches or resumes (`run_arm.sh` calls
   `python`). `python -m pytest -q` must pass in full. Record the count.
3. **Pre-launch controls:** `python runs/RBT-113/prelaunch.py /tmp/rbt113-pre` must end `PRELAUNCH: PASS`. It
   rewrites `runs/RBT-113/controls/prelaunch.txt` and `controls/smoke-readout.txt` for this tree; if the committed
   copy already reads PASS on this `rabbitstew/` tree you may skip it, and either way do not commit them.
4. **The launcher refuses** on: not x86_64 (exit 3); `rabbitstew/` dirty (exit 5); `controls/prelaunch.txt` not
   reading PASS on this `rabbitstew/` tree (exit 7). A refusal is a failure: post it and wake the coordinator.

## 2. Launch (both arms side by side, WORKERS=2)

For each of your two arms, as **harness background tasks** (Bash `run_in_background`; never `nohup` or `&`):
1. `WORKERS=2 runs/RBT-113/run_arm.sh ARM`
   - it writes `platform.txt`, `commit.txt` and the progress manifest, then runs the nine line runs in order.
2. As soon as it is running, find its pid with the **anchored** pattern
   `pgrep -f "^/bin/bash runs/RBT-113/run_arm.sh ARM$"` (an unanchored `pgrep -f "run_arm.sh ARM"` also matches the
   shell that runs it, and a `pkill` with it kills your own shell), and start the durable loop as a second
   background task:
   `DURABLE_WATCH_PID=<that pid> scripts/durable.sh every 20 runs/RBT-113/ARM rbt-113-ARM`

**Post one line on RBT-113** with: your session id and letter; both arms and their checkpoint labels; each arm's
`commit.txt` lines; platform and suite count.

## 3. Check-ins, and restarts

- **Schedule a check-in about every 25 minutes** (`send_later`) until both arms are complete, saved and in PRs. At
  each one, read only: each arm's `state.json` `generation` (of 216); whether `run_arm.sh` and the durable loop are
  alive; `scripts/durable.sh status runs/RBT-113/ARM rbt-113-ARM`.
- **If the container restarted, or `run_arm.sh` is gone before 216/216:**
  1. `scripts/durable.sh restore runs/RBT-113/ARM rbt-113-ARM` (only if the directory was lost);
  2. **re-run** `WORKERS=2 runs/RBT-113/run_arm.sh ARM` as a background task (tested at design time: an arm killed
     mid-run and re-run finished with the interrupted line run byte-identical to an uninterrupted one). It skips complete line runs, resumes a
     started one with `evolve --resume` (byte for byte) and records it in that run's `resumes.txt`;
  3. restart the durable loop with the new pid;
  4. say on the ticket that it was resumed, and from which generation of 216.

## 4. After 216/216: final save, commit by role

For each arm, once `run_arm.sh` has printed `arm ARM complete` and exited:
1. **The final save** (README rule 6): `scripts/durable.sh save runs/RBT-113/ARM rbt-113-ARM`. `status` must read
   216/216.
2. **Check that every file exists**, with `ls` only: `platform.txt` and `commit.txt` in the arm directory, and in
   each of the nine line runs `command.txt`, `config.json`, `lineage.jsonl`, `history.json` (38 files). If one is
   missing, say so on the ticket and wake the coordinator. Never read a missing file as a null.
3. **Commit by allowlisted role, without switching the running checkout's branch** (a separate worktree per arm):

   ```
   git fetch origin claude/new-session-4cao7d
   git worktree add ../wt-ARM -b results/RBT-113-ARM origin/claude/new-session-4cao7d
   cd runs/RBT-113/ARM && for f in platform.txt commit.txt */*/command.txt */*/config.json */*/lineage.jsonl */*/history.json */*/resumes.txt; do
     [ -f "$f" ] && install -D -m 644 "$f" ../../../../wt-ARM/runs/RBT-113/ARM/"$f"; done; cd -
   cd ../wt-ARM && git add runs/RBT-113/ARM && git diff --cached --stat   # 38 files (+ any resumes.txt), each under ~1 MB, nothing else
   git commit -m "RBT-113 ARM: nine line runs, evidence by role" && git push -u origin results/RBT-113-ARM
   ```

   Everything else (genomes, `best_gen*`, `final/`, line runs' `state.json`, `run.log`, the arm's progress manifest)
   is bulk and stays on the checkpoint branch.
4. **Open one PR per arm** against `claude/new-session-4cao7d`, titled `RBT-113 arm ARM`. The body lists the files,
   the checkpoint (216/216), the platform and the `commit.txt` lines, and **no result**.

## 5. Finish

1. **Post on RBT-113:** session letter, both PRs, both checkpoints at 216/216, anything that went wrong (resumes,
   refusals). No result.
2. **Wake the coordinator:** `create_trigger` with `persistent_session_id` `session_01WKXr6PgNkscGhVc7Bzth9k` and the
   prompt "Delegate wake: RBT-113 session Sx done, PRs #a #b"; then `fire_trigger`; then `delete_trigger`.
3. **Failures and questions** go the same way, at once, with the prompt
   "Delegate wake: RBT-113 session Sx, <what>; read it and act".

The designer runs the pre-registered readout once all eight arm PRs are merged:
`python runs/RBT-113/readout.py runs/RBT-113/O[1-4]/[0-9]* runs/RBT-113/Z[1-4]/Z* > runs/RBT-113/readout.txt`.
