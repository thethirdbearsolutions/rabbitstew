## 1. Set up (once per session)

1. **Clone** the integration branch `claude/new-session-4cao7d` at (or after) the merged launch commit, and work in
   that checkout. Do not switch its branch while an arm runs (§4 explains how to commit without switching).
2. **Venv:** `python -m venv ~/venv && ~/venv/bin/pip install -e '.[dev]'`, with no scipy (`python -c "import scipy"`
   must fail). Then `~/venv/bin/python -m pytest -q` must pass in full. Record the count.
3. **Gate, read-only:** `python runs/RBT-112/gate.py runs/RBT-106/H-readout.txt` must print `GATE: LAUNCH`.
4. **The launcher's own checks** refuse on any failure, and you do not work around them:
   - x86_64 (exit 3);
   - clean `rabbitstew/` (exit 5);
   - `runs/RBT-112/cross-ticket-tree-<tree12>.txt` reading SAME RUN on HU-801 and HU-4 for this `rabbitstew/` tree
     (exit 6);

   - founders' digests;
   - no relaunch over an existing run (exit 4).

   A refusal is a failure: post it and wake the coordinator.

## 2. Launch (both arms side by side, WORKERS=2)

For each of your two seeds, as **harness background tasks** (Bash `run_in_background`; never `nohup` or `&`):
1. `WORKERS=2 runs/RBT-112/run_arm.sh HZ SEED`
   - It regenerates and checks the founders, then writes `platform.txt`, `commit.txt`, `command.txt` and the run.
2. As soon as the arm's python process exists (`pgrep -f "out runs/RBT-112/HZ-SEED"`), start its durable loop as a
   second background task:
   `DURABLE_WATCH_PID=<that pid> scripts/durable.sh every 20 runs/RBT-112/HZ-SEED rbt-112-HZ-SEED`

**Post one line on RBT-112** with:
- your session id and session letter;
- both arms and their checkpoint labels `rbt-112-HZ-SEED`;
- each arm's `commit.txt` lines (commit, rabbitstew_tree, certified file);
- platform and suite count.

**Timing:** about 5.1 s per arm-season side by side, so about 51 minutes to season 600. The post-run steps then
take about 40–80 minutes for the pair.

## 3. Check-ins, and restarts

- **Schedule a check-in about every 25 minutes** (`send_later`) until both arms are post-run, saved and in PRs. At each
  one, read only:
  - each `state.json` `season`;
  - whether each arm's python process and durable loop are alive;
  - `scripts/durable.sh status runs/RBT-112/HZ-SEED rbt-112-HZ-SEED`.
- **If the container restarted, or an arm's process is gone before season 600:**
  1. `scripts/durable.sh restore runs/RBT-112/HZ-SEED rbt-112-HZ-SEED`;
  2. resume as a background task with the same workers:
     `python -m rabbitstew.cli ecology --resume --out runs/RBT-112/HZ-SEED --workers 2 >> runs/RBT-112/HZ-SEED/run.log 2>&1`;
  3. restart its durable loop, with `DURABLE_WATCH_PID` set to the new pid;
  4. say on the ticket that it was resumed, and from which season.

  Never relaunch with `run_arm.sh` over an existing run.

## 4. After season 600: post-run, final save, commit by role

1. `runs/RBT-112/postrun.sh HZ SEED`, as a background task. It writes into `runs/RBT-112/HZ-SEED/`:
   - `seasons.txt`, `lineage-last.txt`;

   - `resting.txt`, `freeze.txt`.
2. **Then the final save** (README rule 6): `scripts/durable.sh save runs/RBT-112/HZ-SEED rbt-112-HZ-SEED`.
   `status` must read 600/600.
3. **Check that every file exists**, with `ls` only. Plus `platform.txt`, `commit.txt`, `command.txt` and
   `config.json`, that is 14 files. If one is missing, re-run only the step that writes it, and say so on the
   ticket. Never read a missing file as a null.
4. **Commit by allowlisted role, without switching the running checkout's branch.** Switching it would delete tracked
   files under the other arm. Use a separate worktree per arm:

   ```
   git fetch origin claude/new-session-4cao7d
   git worktree add ../wt-SEED -b results/RBT-112-HZ-SEED origin/claude/new-session-4cao7d

   git commit -m "RBT-112 HZ-SEED: 600 seasons, post-run evidence by role" && git push -u origin results/RBT-112-HZ-SEED
   ```
